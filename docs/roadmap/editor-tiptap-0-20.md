# 블록 편집기: Tiptap 3 이전 (0.20.0)

2026-11-23. 사용자 요청: 추천대로 Tiptap 3로 옮기고, 노션 이상 품질로 다시 디자인, 기본 곡선은 ease-out.

## 결정
- 편집 엔진은 Tiptap 3 / ProseMirror (MIT 패키지만: core, react, pm, extensions, extension-table). 저장은 마크다운 그대로, 변환은 우리 것(`cms-blocks-convert.ts` → 평평한 블록 → `cms-blocks-pm.ts` → ProseMirror 문서).
- 모든 블록 노드에 `bid`. 손대지 않은 블록은 원문 바이트 그대로(지문은 ProseMirror 모델 기준으로 다시 계산: `refreshFingerprints`). 문서 앞뒤 빈 줄은 `keepEdges`.
- 구조 편집(들여쓰기, 옮기기, 바꾸기, 2단)은 기존 `cms-blocks-tree.ts` 함수로 하고, 결과를 문서 차이만큼만 바꿔 한 번의 되돌리기 단위로 넣음.
- 엔진 패키지는 `cms-block-editor` 레지스트리 항목에만. 지킴 테스트가 다른 화면과 패키지 의존성에 들어오는 것을 막음.

## 리뷰 1차 (UX, 로직, 노션 대비) 반영
P0: 블록 잘라내기(클립보드 실패 시 삭제), `---` 단축 입력이 글을 지움, 바깥 변경이 조합 중 입력·원문 블록 초안을 덮음 → 고침.
P1: 표 열 추가와 정렬의 되돌리기, Enter+선택 되돌리기, 내부 복사·붙여넣기 속성(캡션, 언어, 정렬), 업로드 자리표시, 코드 안 ``` 줄, `1. 1.` 목록 번호, Tab 탈출, Esc와 전체 화면, 슬래시 메뉴 화면 낭독, 휴대폰 옵션 버튼·표 막대·키보드 위 팝오버, 깨진 그림 상태, 링크 범위·⌘클릭·주소 붙여넣기, ⌘A 두 번, 블록 메뉴 위·아래에 추가 → 고침.

## 리뷰 2차·3차 (고친 것만 다시 봄)
- 2차 P0: 코드 펜스 안의 `:::html`을 HTML 검사가 놓침(펜스 스캐너를 파서와 같게, `fenceTracker`), 원문 블록 편집 중 들어온 바깥 변경이 Done에 덮임(줄 단위 3방향 병합, 충돌은 양쪽 보존과 알림). P1: 바깥 변경 뒤 `1. 1.` 목록 번호, 바깥 변경에 올리는 중인 그림 자리 사라짐, 여러 칸 선택한 표의 머리 행 삭제와 정렬, 복사한 링크가 붙여넣기에서 빠짐 → 고침.
- 3차 P1: 기다리던 바깥 변경이 되돌려지면 편집 내보내기가 멈춤, 토글·2단 안의 올리는 중 그림, 모든 열 삭제 시 정렬만 지워짐, 펜스 여는 줄 판정이 파서와 다름 → 고침. 리뷰는 규칙대로 3차에서 멈춤.

## 남은 것 (다음에)
- 저장소 설정이 없는 앱에서 휴대폰의 `/admin/files`에 메뉴 버튼이 없음(레이아웃 테스트가 S3 없이 돌 때 잡음). 편집기와 무관, 확인 필요.
- 노션식: 블록에 링크 복사(마크다운에 블록 id 문법이 필요), 다른 문서로 옮기기, 표 범위 붙여넣기(TSV)·채우기·행/열 끌어 옮기기, 모든 토글 펼치기/접기, ⌘클릭으로 블록 하나씩 더하기, 휴대폰에서 끌어 옮기기 모드.
- 빈 2단 칸 전용 놓기 자리, 알림 상자 아이콘을 눌러 종류 바꾸기.
- 긴 문서(수천 블록)에서 타이핑마다 전체 직렬화 비용: 측정과 블록별 캐시.
- 글자색·배경색, 토글 제목, 2단 너비: 마크다운 문법을 정하기 전에는 넣지 않음.
- 편집기 위쪽 필드를 접어 글쓰기 칸을 먼저 보이게 하는 문서 편집기 배치(리뷰 디자인 제안 1).
