**작업 방식** (사용자가 정한 것)

- 리뷰 에이전트는 최대 3차: 1차는 관점이 다른 리뷰어 셋을 함께, P0/P1만 고치고 회귀 테스트, 2차는 고친 것만 본다. "지적이 바닥날 때까지" 돌리지 않는다. P2/P3는 PR 본문과 이 폴더의 리뷰 문서에 적는다.
- 큰 UI 부품은 라이브러리를 넣지 않고 직접 쓴다. 예외는 블록 편집기의 편집 엔진(Tiptap 3 MIT 패키지, 2026-11-23 사용자 결정). `src/parts.test.ts`가 그 엔진을 `cms-block-editor` 항목 밖에서, 다른 편집기 라이브러리는 어디서든 막는다. 한국어 화면 문구는 음슴체.
- 명령은 늘 `npx @mainsoft/agent-cms …` 전체 이름.
- 새 REST 경로는 `src/openapi.ts`의 `API_ROUTES`와 `src/cms.ts`의 `RESERVED_ROUTES`에 한 줄씩.
- registry 화면을 고치면 `examples/next/components/cms`의 복사본도 고친다.
- **운영 docs 사이트(agent-cms-docs.vercel.app)의 코드와 문서 본문은 이 저장소에 없다** (2026-11-23에 옮김). 그 사이트는 npm의 이 패키지를 쓰고, `/r` 화면 목록은 `npx @mainsoft/agent-cms registry build`로 만든다. 새 기능의 사용 설명 페이지도 그쪽에서 쓴다. 이 저장소의 README, CHANGELOG, `UPGRADE-*.md`는 그대로 여기서 쓴다.
- `main`에 패키지 변경이 머지되면 npm `next` 태그로 미리보기 버전이 자동으로 나간다(`publish.yml`). 다른 앱에서 배포 전 변경을 시험할 때 쓴다.
- 배포 순서: PR → CI → 머지 → `vX.Y.Z` 태그 → GitHub 릴리스 → Publish 워크플로가 npm에 올림 → 빈 폴더 설치와 운영 docs 사이트로 확인.

8. 끝나면 실제 화면 스크린샷을 전부 모아 보여 준다.
9. 이 저장소에는 모델을 부르는 코드를 넣지 않는다. 모델 호출 라이브러리를 불러오지 않고 의존성에도 두지 않는다 (테스트로 지킨다).
10. 코딩 에이전트의 세션 파일(`.slash`)은 커밋하지 않는다. 이 문서들이 가리키는 화면 시안만 예외다 (`.gitignore`).

## 묶음 문서를 읽는 법

항목마다 같은 순서로 적었다.

- **무엇을, 왜**: 기능과 그것이 없어서 생기는 문제. 참고한 CMS.
- **데이터**: 새 테이블과 열. 스키마 버전이 오르면 `upgradeSteps()`에 단계를 추가하고 `UPGRADE-<버전>.md`를 쓴다.
- **API와 도구**: REST 경로, `cms.*` 메서드, 에이전트 도구, CLI.
- **화면**: 시안의 화면 번호. 시안이 없으면 "시안에 없는 화면"에 따로 모았다.
- **정해 둔 기본값**: 묻지 않고 정한 값. 구현하면서 바뀌면 이 표를 고친다.
- **끝났다고 보는 기준**: 테스트로 확인할 수 있는 문장.

모든 묶음에 공통인 규칙:

- 새 화면 문구는 영어와 한국어를 `cms-messages.ts`에 함께 넣는다. 한국어는 지금처럼 "~어요" 말투.
- 새 오류는 `ERROR_CODES`와 두 문구 카탈로그에 함께 넣는다.
- 새 기능은 설정하지 않으면 꺼져 있다. 기존 앱은 `migrate apply` 말고 바뀌는 것이 없어야 한다.
- 에이전트 도구는 `tools.ts` 한 곳에 넣어 MCP와 CLI가 함께 쓰고, `./tools`의 `toolsFor`와 `callTool`로 어떤 에이전트 틀에든 붙일 수 있게 한다. 권한은 키의 범위(read, write, publish, admin)를 따른다.
- 모델을 불러야 하는 기능은 만들지 않는다. 필요하면 확장 자리(134번)나 플러그인 연결구(92번)를 만들고 기능은 밖에 둔다.
- 사람이 하는 일과 에이전트가 하는 일은 감사 로그에 같은 형식으로 남는다.
- 화면 부품은 복사형 레지스트리(`registry/cms`)에 넣고 `registry.json`에 항목을 추가한다.
