## 2. 관계 필드

**무엇을, 왜.** 글의 저자, 관련 문서처럼 다른 문서를 가리키는 값. 지금은 주소를 글자로 적어야 하고, 가리킨 문서가 지워져도 모른다.

**어떻게.**

```ts
fields: z.object({
  author: relation("people").optional(),
  related: relation(["guide", "posts"], { many: true, max: 5 }).default([]),
})
```

- 값은 문서 ID다 (주소가 아니다). 가리킨 문서의 주소가 바뀌어도 관계가 유지된다.
- 표 `cms_doc_refs(from_document_id, to_document_id, field, in_draft, in_published)`. 0.8.0의 파일 사용처와 같은 방식으로 저장할 때 다시 계산한다.
- 읽을 때 `?expand=author,related`를 주면 가리킨 문서의 제목, 주소, 요약, 상태를 함께 준다. 한 단계만 펼친다.
- 진단: `relation_missing`(오류, 없는 문서), `relation_wrong_collection`(오류), `relation_unpublished`(경고, 게시된 문서가 게시되지 않은 문서를 가리킴).
- 가리켜지고 있는 문서를 지우거나 숨기려 하면 가리키는 문서 목록을 보여 주고 확인받는다 (파일 삭제와 같은 창).
- 공개 화면용 `cms.related(doc, field)`.
- 에이전트: 문서 도구의 입력에서 관계 필드는 `{ collection, slug }`로도 받는다. 도구가 ID로 바꿔 저장한다.

**화면.** 시안 2번 (Author, Related, 문서 선택 창).

## 4. 문서 트리와 순서

**무엇을, 왜.** 안내서는 목차가 있다. 지금은 분류 안에서 수정한 시각 순이라 순서를 정할 수 없다.

**데이터.** `cms_documents`에 `parent_id`, `position`.

**동작.**

- 컬렉션 설정 `tree: true`(또는 `tree: { maxDepth: 3 }`)로 켠다. 켜지 않은 컬렉션은 그대로다.
- 끌어서 순서와 부모를 바꾼다. 자기 자손 밑으로는 옮길 수 없다.
- 순서 변경은 버전을 만들지 않는다 (내용이 아니다). 감사 로그에는 남는다.
- 자식이 있는 문서는 지울 수 없다. 자식을 먼저 옮기거나 지우라고 알려 준다.
- 주소는 트리와 따로다 (`/guide/install`이지 `/guide/getting-started/install`이 아니다). 주소에 부모를 넣고 싶은 앱은 `url()`에서 `cms.ancestors(doc)`를 쓴다.
- `cms.tree(collection)`이 공개 화면의 사이드바에 쓸 목차를 돌려준다.
- 초안과 게시된 문서의 트리는 하나다. 게시되지 않은 문서는 공개 목차에서 빠지고, 그 자식은 한 단계 위로 붙어 보인다.

**API와 도구.** `POST /collections/:c/_move { id, parentId, before }`. 도구 `move_document`(write), `get_tree`(read).

**화면.** 시안 1번.

## 5. 다국어

**무엇을, 왜.** 같은 문서를 여러 언어로. 원문이 바뀌면 번역이 낡았다는 것을 알아야 한다.

**데이터.** 언어마다 문서 행 하나. `cms_documents`에 `locale`, `group_id`(같은 문서의 언어들을 묶음), `source_version`(이 번역이 원문의 몇 번째 버전을 보고 만든 것인지). 유일 조건이 `(collection, slug)`에서 `(collection, slug, locale)`로 바뀐다.

**왜 행을 나누나.** 언어마다 버전 기록, 게시 상태, 검토, 예약이 따로 있어야 한다. 영어만 먼저 게시하고 일본어는 초안으로 둘 수 있다. 한 행에 언어별 내용을 넣으면 이 모든 것을 다시 만들어야 한다.

**동작.**

- `createCms({ locales: ["ko", "en", "ja"], defaultLocale: "ko" })`, 컬렉션마다 `localized: true`. 설정하지 않으면 지금과 같다 (언어 값은 빈 값).
- 원문은 기본 언어의 문서다. 번역 탭의 상태: "원문", "번역 필요"(원문이 그 뒤 게시됨), 최신, "없음".
- 필드마다 번역할지를 정한다 (`admin.fields.x.localized: false`). 번역하지 않는 필드(날짜, 관계, 이미지)는 원문의 값을 따라가고 번역 화면에서 고칠 수 없다.
- "바뀐 곳 보기"는 원문의 `source_version`과 지금 버전의 diff를 보여 준다 (0.6.0의 diff 화면).
- 시안 3번 배너의 "번역 초안 만들기"는 모델을 부르는 기능이라 이 패키지가 만들지 않는다. 그 자리에 확장 자리 `localeAction`(134번)만 두고, 비어 있으면 버튼이 보이지 않는다. 사람이 번역을 저장할 때 "원문 v7 기준으로 맞춤"을 고르면 `source_version`이 올라간다.
- 주소는 언어마다 다르게 둘 수 있다. 기본은 원문과 같은 주소.
- 읽기: `cms.get(col, slug, { locale, fallback: true })`. 번역이 없으면 원문을 준다.
- 검색은 언어마다 색인을 나눈다. 한글 2-gram은 한국어에만 쓴다.
- 도구: 문서 도구 전부에 `locale` 인자. `list_translations`(read)가 언어별 상태를 준다.

**이행.** 기존 문서는 `locale`이 빈 값이고, 다국어를 켜면 `migrate`가 기본 언어로 채운다. 스키마 변경이 큰 편이라 `UPGRADE-0.11.md`에 순서를 적는다.

**화면.** 시안 3번.

## 112. 단일 문서

**무엇을, 왜.** 사이트 이름, 메뉴, 바닥글처럼 하나만 있는 내용. 지금은 문서가 하나뿐인 컬렉션을 만들어 흉내 내야 한다 (Payload globals, Strapi single types).

**어떻게.** `defineSingle({ slug: "site", label: "사이트 설정", fields, visibility })`. 안에서는 문서가 하나로 고정된 컬렉션이다. 그래서 버전 기록, 초안과 게시, 권한, 다국어, 웹훅이 그대로 된다.

- 사이드바에서 컬렉션들 아래에 보이고, 누르면 목록 없이 바로 편집 화면이다.
- 본문(마크다운)은 기본으로 숨긴다 (`body: true`로 켠다). 주소와 분류 입력도 없다.
- 읽기 `cms.single("site")`, REST `GET /singles/site`. 도구 `get_single`, `update_single`.
- 첫 저장 전에는 기본값으로 읽힌다.

**화면.** 시안 4번.

## 41. 템플릿, 42. 스니펫

- **41.** 컬렉션 설정 `templates: [{ key, label, summary, body, fields }]`. "새 문서"를 누르면 템플릿을 고른다 (시안 5번). 템플릿이 없는 컬렉션은 지금처럼 바로 만든다. `cms.create(..., { template })`, 도구 `list_templates`(read)와 `create_document`의 `template` 인자. 사람과 에이전트가 같은 뼈대에서 시작한다.
- **42.** 본문에 `[[snippet:key]]`를 쓰면 다른 문서의 본문이 그 자리에 들어간다. 스니펫은 `snippets: true`인 컬렉션의 문서다. 서로를 넣는 순환은 저장할 때 막는다. 스니펫을 쓰는 문서 목록을 편집 화면에 보여 준다. 검색 색인에는 펼친 내용으로 들어가고, 스니펫이 바뀌면 그것을 쓰는 문서도 다시 색인한다.

## 3. 블록 본문

**무엇을, 왜.** 마크다운을 모르는 사람도 콜아웃, 단계, 표, 영상을 넣을 수 있어야 한다.

**어떻게: 저장은 계속 마크다운이다.** 블록을 JSON 배열로 따로 저장하면 diff, 섹션 패치, 검색, 3-way 병합, 에이전트 도구를 전부 다시 만들어야 한다. 그래서 마크다운 문법을 넓히고, 그 위에 블록으로 보이는 편집 화면을 얹는다.

| 블록 | 문법 |
|---|---|
| 제목, 문단, 목록, 인용, 코드 | 지금 그대로 |
| 이미지, 영상, 파일 | 0.8.0의 `![alt](asset:id/name "캡션")` |
| 콜아웃 | 지금 있는 `> [!note]` |
| 단계 | `:::steps` 안의 번호 목록 |
| 표 | GFM 표 |
| 링크 카드 | `:::card` 안의 링크 한 줄 |
| 영상 (외부) | `:::video` 안의 주소 한 줄 (허용한 사이트만) |

- 편집기 위의 "마크다운 / 블록" 전환은 같은 글을 두 가지로 보여 줄 뿐이다. 블록 화면에서 고치면 그 블록의 마크다운만 바뀐다.
- 블록으로 나타낼 수 없는 마크다운은 "마크다운" 블록으로 그대로 보인다. 아무것도 잃지 않는다.
- 에이전트는 지금처럼 마크다운과 섹션 패치를 쓴다. 도구 설명에 새 문법을 적는다.
- 앱은 `renderBlocks(blocks, components)`(36번, 묶음 2)로 블록마다 자기 컴포넌트를 쓴다.
- 묶음 2의 섹션 단위 편집기(48번)가 이 화면의 일부가 된다.

**화면.** 시안 6번.

## 39. 슬러그 도우미와 게시 후 주소 변경, 125. 리다이렉트 관리

**무엇을, 왜.** 지금은 게시한 문서의 주소를 바꿀 수 없다. 오타가 난 주소를 영원히 써야 한다.

**데이터.** `cms_redirects(id, from_path, to_path, status, source, document_id, hits_30d, created_by*, created_at)`.

**동작.**

- 제목을 쓰면 주소를 제안한다 (`suggestSlug()`). 한글 제목은 로마자로 바꾸고 겹치면 번호를 붙인다. 사람이 고치면 제안을 멈춘다.
- 게시한 문서의 주소를 바꿀 수 있게 한다. 바꾸면 예전 주소에서 새 주소로 가는 리다이렉트가 자동으로 생긴다 (시안 9번의 "자동"). 확인 창이 "예전 주소는 새 주소로 넘어가요"라고 알린다.
- 직접 만든 리다이렉트도 같은 표에 있다 (시안의 "직접"). 301과 302.
- 고리(가 → 나 → 가)와 두 번 넘어가는 것(가 → 나 → 다)은 저장할 때 정리한다.
- 앱의 미들웨어가 `cms.resolveRedirect(path)`를 부른다. 메모리에 올려 두므로 DB를 읽지 않는다. 묶음 6의 Next 도구(99번)가 이 미들웨어를 준다.
- 조회 수는 하루 단위로 센다 (`cms_hits`와 같은 방식).
- 예전 주소로 새 문서를 만들면 그 리다이렉트를 지울지 묻는다.

**API와 도구.** `GET/POST /redirects`, `PATCH/DELETE /redirects/:id`. admin 범위. 도구 `list_redirects`(read)만 낸다.

**화면.** 시안 9번.

## 124. SEO 도구

**데이터.** `cms_documents.seo jsonb`: `{ title, description, image(파일 ID), canonical, noindex }`. 버전 스냅샷에 들어간다.

**동작.**

- 컬렉션 설정 `seo: true`로 켠다. 비워 두면 문서의 제목, 요약, 첫 이미지를 쓴다.
- `cms.seoFor(doc)`가 채워진 값을 준다. Next의 `generateMetadata`에 바로 넣을 수 있는 모양으로 돌려주는 도우미는 묶음 6의 Next 도구에 넣는다.
- 진단(경고): 제목이 60자를 넘음, 설명이 160자를 넘음, 설명이 비어 있음, 공유 이미지가 1200x630보다 작음.
- `cms.sitemap(collections)`가 게시된 문서의 주소와 수정 시각을 준다. `noindex`인 문서는 뺀다.
- 설명 칸에도 필드 옆 확장 자리(`fieldAction`, 134번)가 붙는다.
- 에이전트: 문서 도구의 입력에 `seo`가 들어간다.

**화면.** 시안 8번.

## 123. 폼 빌더

**무엇을, 왜.** 문의, 신청 같은 폼을 CMS에서 만들고 제출을 모은다 (Payload form-builder). 사용자가 로드맵에 넣었다.

**데이터.** `cms_forms(id, slug, name, fields jsonb, settings jsonb, enabled, version)`, `cms_form_submissions(id, form_id, form_version, data jsonb, files[], ip_hash, user_agent, spam, created_at)`.

**동작.**

- 필드 종류: 한 줄 글, 여러 줄 글, 이메일, 숫자, 선택, 여러 개 선택, 체크, 날짜, 파일.
- 공개 제출 주소 `POST /api/cms/forms/:slug`. 이 라이브러리에서 로그인 없이 쓰는 유일한 길이므로 따로 막는다:
  - 보이지 않는 미끼 칸(채우면 스팸으로 표시하고 성공한 것처럼 답한다)
  - IP마다 분당 5번
  - 앱이 주는 `forms.verify(req)` 함수 (캡차를 붙이는 자리)
  - 본문 한도 64KB, 필드 종류와 길이를 서버가 다시 검사
- 파일 칸은 비공개 저장소로 올라간다. 0.8.0의 올리기를 쓰되 한 번만 쓸 수 있는 짧은 허가를 준다. 허용 형식과 크기는 필드마다.
- 제출이 오면 `form.submitted` 이벤트가 난다 (웹훅, 자동화). 메일 알림은 앱이 주는 `forms.notify`로.
- 제출은 CSV로 내려받는다. 보존 기간은 `retention.submissionsDays`(기본 365일).
- IP는 해시로만 저장한다.
- 폼을 고치면 `version`이 오르고, 제출은 그때의 버전을 기억한다.
- 앱에 넣기: 복사형 부품 `<CmsForm slug="contact" />` (시안의 "넣는 코드"). 다른 프레임워크는 제출 주소와 필드 정의(`GET /forms/:slug`)를 써서 직접 그린다.
- 에이전트 도구로는 내지 않는다. 제출 내용에는 개인 정보가 있다. admin 범위 키가 REST로 읽을 수는 있다.

**화면.** 시안 7번 (필드 탭). 제출 탭, 설정 탭, 폼 목록은 시안에 없다.

| 트리의 순서 변경 | 버전을 만들지 않음 | 내용이 아니다 |
| 주소와 트리 | 따로 | 문서를 옮겨도 주소가 깨지지 않는다 |
| 다국어 저장 | 언어마다 행 하나 | 버전, 게시, 검토, 예약이 언어마다 따로 돌아간다 |
| 번역이 없을 때 읽기 | 원문을 준다 | `fallback: false`로 끌 수 있다 |
| 단일 문서의 본문 | 숨김 | 설정 값이 주 용도다 |
| 블록 본문의 저장 | 마크다운 | diff, 패치, 검색, 병합, 에이전트 도구를 그대로 쓴다 |
| 주소를 바꾸면 | 301 리다이렉트를 자동으로 | 밖에 걸린 링크가 살아 있게 |
| SEO 길이 경고 | 제목 60자, 설명 160자 | 검색 결과에서 잘리는 대략의 길이. 컬렉션 설정으로 바꿀 수 있다 |
| 폼 제출의 IP | 해시만 저장 | 개인 정보를 줄인다 |
| 폼을 에이전트 도구로 내는가 | 내지 않는다 | 제출 내용에 개인 정보가 있다 |
| 폼 제출 보존 | 365일 | 설정으로 바꾼다 |

## 끝났다고 보는 기준

- 관계 필드로 가리킨 문서의 주소를 바꿔도 관계가 유지되고, 지우려 하면 가리키는 문서 목록이 뜬다
- 에이전트가 `{ collection, slug }`로 관계를 넣을 수 있고, 없는 문서면 `relation_missing`이 온다
- 트리에서 문서를 끌어 옮기면 `cms.tree()`의 결과가 바뀌고 버전은 늘지 않는다
- 원문을 게시하면 번역 탭이 "번역 필요"가 되고, "바뀐 곳 보기"가 그 사이의 diff를 보여 준다
- 다국어를 켜지 않은 앱은 이전 버전의 테스트가 그대로 통과한다
- `cms.single("site")`가 저장 전에는 기본값을, 게시 뒤에는 게시된 값을 준다
- 블록 화면에서 블록 하나를 고치면 마크다운의 다른 줄은 한 글자도 바뀌지 않는다 (여러 문서로 왕복 테스트)
- 게시한 문서의 주소를 바꾸면 `resolveRedirect(예전 주소)`가 새 주소를 준다. 고리는 만들 수 없다
- 폼의 미끼 칸을 채운 제출은 스팸으로 표시되고, 분당 6번째 제출은 429다
- 접근성 검사(axe)가 새 화면 전부에서 통과한다. 끌어서 옮기는 것은 모두 키보드로도 된다
- 실제 화면을 시안 9개와 같은 크기로 찍어 비교한다

| 한 것 | 어떻게 |
|---|---|
| 보관(archive) 때 가리키는 문서 확인 | 삭제와 같다: `409 doc_referenced`와 목록, `force`로 진행. `cms.archive(…, { force })`, `POST …/archive` 본문 `{ force: true }`, `archive_document`의 `force`, `client.archive(c, s, v, { force })`. 어드민은 목록의 행·일괄 동작과 편집기 더보기 메뉴(숨기기·숨김 해제 추가)에서 `ReferencedDialog`를 "그래도 숨기기"로 연다 |

| 리다이렉트 일별 방문 수 | `cms_redirect_hits(redirect_id, day, n)`. 목록에 `hits30d`·`daily`(30일), `GET /redirects/:id/hits?days=`(최대 90일). 화면에 "30일 조회" 열과 작은 막대 그림(SVG, 숫자 요약을 aria-label로)과 정렬. 보존 기간은 `retention.redirectHitsDays`(리다이렉트를 켜면 기본 90일) |

| 인용 검증의 앵커 별칭 | `lookupForAgent`가 `aliases`(옛 인용 id → 지금 id)를 돌려주고, `verifyCitations`가 옛 앵커를 받아 지금 id로 바꿔 준다(`renamedFrom`) |
| 트리 이동의 동시성 | 한 컬렉션의 이동은 하나씩: 프로세스 안에서는 큐, Postgres에서는 트랜잭션 안의 `pg_advisory_xact_lock`(`CmsRepo.lockTree`). 서버 둘이 반대로 옮기는 테스트(pglite·Postgres) |
| 줄 안의 스니펫 | 글 줄 안의 `[[snippet:key]]`도 스니펫이 문단 하나면 그 글로 채운다. 여러 블록이면 토큰을 두고 편집자에게 `snippet_inline_multi` 경고. 공개 읽기·검색 색인만 채우고 편집용 읽기·`?snippets=raw`는 토큰 그대로, 쓰는 곳 목록에 줄 안 사용도 센다 |
| 작은 것 | `list_templates`(와 `GET …/_templates`)는 읽기 권한만. `cms.resolveRedirect(path)`, `cms.seoFor(doc)`(계획의 이름; `cms.redirects.resolve`, `cms.seoOf`도 남김). 문서를 따라가는 리다이렉트의 주소는 30초 캐시 + 같은 서버의 저장·게시·이동·삭제 때 바로 비움 |
