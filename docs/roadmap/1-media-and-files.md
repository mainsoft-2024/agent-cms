## 108. 버킷 파일 관리자

**무엇을, 왜.** 미디어 라이브러리는 CMS로 올린 파일만 보여 준다. 사용자는 "버킷 전체"를 관리하고 싶어 했다. 다른 프로그램이 넣은 파일, 예전에 올려 둔 파일도 폴더로 탐색하고, 옮기고, 지우고, 링크를 만들어 보낼 수 있어야 한다.

**어떻게 동작하나.**

- 목록은 저장소에 직접 묻는다: `adapter.list({ prefix, delimiter: "/", cursor, limit })`. 결과를 `cms_assets`와 `(store, key)`로 맞춰, CMS가 아는 파일에는 대체 텍스트, 태그, 사용처를 붙인다.
- CMS가 모르는 파일은 행을 미리 만들지 않는다. 그 파일을 열어 정보를 고치거나, 문서에 넣거나, 공유 링크를 만들 때 행을 하나 만든다 ("등록"). 버킷에 파일이 백만 개 있어도 표가 커지지 않는다.
- 한꺼번에 등록하고 싶으면 CLI `agent-cms storage sync --store <이름> [--prefix <경로>]`를 쓴다. 종류와 크기를 읽어 행을 만든다. 저장소에서 사라진 파일의 행은 "없어짐"으로 표시하고 지우지 않는다 (문서가 가리키고 있을 수 있다).
- 이동과 이름 변경은 복사한 뒤 원본을 지운다 (S3에는 이동이 없다). 5GB가 넘는 파일은 조각 복사를 쓴다.
- 폴더 이동은 안의 파일을 하나씩 옮긴다. 화면에서는 1,000개까지, 그보다 많으면 CLI `agent-cms storage move`로 안내한다. 중간에 실패하면 옮긴 것과 남은 것을 보고하고, 다시 실행하면 남은 것만 옮긴다.
- 삭제는 0.8.0과 같은 규칙이다: 사용 중이면 문서 목록을 보여 주고 확인받는다. 폴더를 지울 때는 안에 있는 파일 수와 사용 중인 파일 수를 보여 준다.
- "검색"은 지금 폴더 안에서 이름의 앞부분으로 찾는다 (저장소가 지원하는 방식). 버킷 전체에서 이름 일부로 찾는 것은 등록된 파일에 한해 된다.

**공유 링크.** 파일 하나에 기한이 있는 주소를 만든다.

- 기한은 1시간, 24시간, 7일 중에서 고른다. S3의 서명 주소는 7일이 한도다.
- 공개 저장소의 파일은 공개 주소를 그대로 준다 (기한 없음).
- 만들 때마다 감사 로그에 `asset.share`를 남긴다. 만든 링크를 나중에 끊을 수는 없다 (서명 주소의 성질). 이 사실을 README에 적는다.
- 여러 파일을 고르면 파일마다 하나씩 만들어 목록으로 보여 준다.

**데이터.** 새 테이블 없음. `cms_assets`에 `source`(`cms` 또는 `external`)와 `missing_at` 열을 추가한다.

**API와 도구.**

| 경로 | 용도 |
|---|---|
| `GET /stores/:store/files?prefix=&cursor=&q=` | 버킷 탐색 (폴더와 파일) |
| `POST /stores/:store/files/_register` | 모르는 파일 등록 |
| `POST /stores/:store/files/_move` | 여러 파일이나 폴더 이동 (작업 ID를 돌려주고 진행을 조회) |
| `POST /stores/:store/files/_delete` | 여러 파일 삭제 |
| `POST /assets/:id/share` | 공유 링크 |

에이전트 도구 3개: `list_store_files`(read), `register_asset`(write), `create_share_link`(publish). 여러 파일 이동과 삭제는 도구로 내지 않는다. 에이전트는 0.8.0의 `move_asset`, `delete_asset`을 파일마다 부른다.

**권한.** 버킷 탐색은 저장소의 `access.read`. 이동, 삭제, 공유 링크는 0.8.0의 삭제와 같은 수준 (사람은 관리자, 키는 publish). 저장소마다 `access.browse`로 탐색만 따로 막을 수 있다 (기본은 `read`와 같음).

**화면.** 시안 8번. 메뉴 "파일"은 탐색 권한이 있을 때만 보인다. 미디어 화면과의 차이: 미디어는 CMS가 아는 파일을 종류와 태그로 찾는 곳이고, 파일은 버킷을 있는 그대로 보는 곳이다. 파일 화면에서 파일을 누르면 미디어의 파일 정보 패널(시안 2번)이 같은 모습으로 열린다.

## 109. Vercel Blob 어댑터

**무엇을, 왜.** Vercel에 올리는 앱은 S3 계정 없이 Vercel Blob을 바로 쓸 수 있다. 사용자가 S3 호환 다음으로 골랐다.

**어떻게.** `@mainsoft/agent-cms/storage-vercel-blob`의 `vercelBlobStorage({ token, access })`. `@vercel/blob`은 선택 peer 의존성이다.

- 브라우저 올리기는 서명 주소가 아니라 토큰 교환이다. 서버가 `handleUpload()`로 짧은 토큰을 내주고 브라우저가 그 토큰으로 올린다. 그래서 "올리는 방법"의 종류가 하나 늘어난다 (`kind: "vercel-blob"`). 브라우저 쪽 `cms-upload.ts`는 이 종류일 때만 `@vercel/blob/client`를 불러온다.
- 조각 올리기와 재시도는 Vercel의 것을 쓴다.
- 공개 저장소와 비공개 저장소를 `access` 값으로 나눈다.

**확인한 것 (Vercel 문서, 2026-11-19).** 비공개 저장(`access: "private"`), 브라우저 올리기(토큰 교환), 조각 올리기(100MB 이상에 권장)가 있다.

**확인하지 못한 것.** 목록, 복사, 삭제, 머리 읽기가 연결 규격의 모양에 그대로 맞는지. 비공개 파일을 여는 주소를 어떻게 만들고 기한을 줄 수 있는지 (공유 링크의 기한 선택이 되는지가 여기에 달렸다). Vercel Blob이 경로에 무작위 접미사를 붙이는 기본 동작을 끌 수 있는지 (경로가 사람이 읽는 그대로여야 한다). 시작할 때 먼저 확인하고, 안 되는 것은 "이 저장소에서는 지원하지 않음"으로 화면과 `storage check`에 드러낸다.

**검증.** 저장소 계약 테스트를 Vercel Blob에도 돌린다. 실제 토큰이 필요하므로 CI에서는 토큰이 있을 때만 돈다. 토큰이 없으면 건너뛰었다고 출력한다.

## 110. 선택형 서버 이미지 변환 모듈

**무엇을, 왜.** 0.8.0은 원본만 저장하고 크기 변환을 앱이나 CDN에 맡긴다. Next.js는 이미지 기능이 있어 괜찮지만, 사용자는 다른 프레임워크와 단독 서버까지 갈 계획이라 자체 기능이 조금 있어야 한다고 했다. 설치를 무겁게 만들지 않도록 원하는 앱만 켜는 모듈로 둔다.

**어떻게.** `@mainsoft/agent-cms/image-sharp`. `sharp`는 선택 peer 의존성이다.

```ts
import { sharpTransforms } from "@mainsoft/agent-cms/image-sharp";

media: {
  transforms: sharpTransforms({
    presets: { thumb: { width: 480 }, card: { width: 800, height: 450, fit: "cover" }, full: { width: 1600 } },
    formats: ["webp"],
  }),
}
```

- **미리 정한 크기만** 만든다. 주소에 아무 숫자나 넣을 수 없다. 남용을 막는 가장 단순한 방법이다 (Directus의 프리셋과 한도 방식).
- 주소: `/api/cms/files/<id>/<이름>?size=card`. 처음 요청 때 만들고 `_cms/derived/<id>/card.webp`에 저장한다. 다음부터는 그 파일로 넘긴다.
- 한도: 긴 쪽 최대 4096px, 동시에 4개, 한 건 10초. 넘으면 원본으로 넘긴다.
- 원본이 지워지거나 바뀌면 만든 사본도 지운다.
- `cms.imageUrl(asset, { size: "card" })`가 이 주소를 돌려준다. 모듈이 없으면 0.8.0처럼 앱의 `imageUrl` 연결구를 쓴다.
- **에이전트가 가져온 이미지의 썸네일**: 0.8.0에서는 브라우저가 썸네일을 만들기 때문에 에이전트가 올린 파일은 썸네일이 없다. 이 모듈이 있으면 가져올 때 서버가 만든다.
- **초점**: 파일 정보 패널에서 이미지의 한 점을 찍으면 `fit: "cover"`로 자를 때 그 점이 남는다. `cms_assets`에 `focal_x`, `focal_y`(0~1) 열을 추가한다.
- **자르기**: 원본을 바꾸지 않는다. 초점과 미리 정한 크기로 해결한다. 원본을 잘라 새 파일로 저장하는 편집기는 만들지 않는다.

**동작하는 곳.** `sharp`는 Node 런타임에서만 돈다. Edge 런타임에서는 켤 수 없고, 켜려 하면 부팅 때 오류를 낸다.

## 130. 미디어 후속

0.8.0에서 뺀 것들이다. 0.9.0에 함께 넣되, 시간이 모자라면 이 순서로 뒤로 미룬다.

| 순서 | 무엇 | 어떻게 |
|---|---|---|
| 1 | 어드민에서 URL로 가져오기 | 올리기 버튼 옆 메뉴에 "URL에서 가져오기". 0.8.0의 `import_asset`과 같은 경로, 같은 차단 규칙 (Payload pasteURL) |
| 2 | 같은 주소로 파일 교체 | 파일 정보 패널의 "바꾸기". ID와 경로는 그대로 두고 내용만 바꾼다. 문서를 고치지 않아도 새 파일이 보인다. CDN 캐시는 앱의 몫이라고 적는다 |
| 3 | 사진 위치 정보 지우기 | `media.stripMetadata: true`면 올리기 전에 브라우저가 JPEG의 위치 정보를 지운다. 기본은 꺼짐 (Directus는 허용 목록 방식) |
| 4 | 새로 고친 뒤 올리기 이어 하기 | 올리던 파일의 ID와 끝난 조각을 브라우저 저장소에 적어 두고, 같은 파일을 다시 고르면 남은 조각만 올린다 |
| 5 | 바이러스 검사 연결구 | `media.scan(asset)` 함수를 앱이 준다. 검사가 끝날 때까지 `status: "scanning"`이고 문서에 넣을 수 없다. 검사기는 넣지 않는다 |

## 정해 둔 기본값

| 항목 | 값 | 이유 |
|---|---|---|
| 모르는 파일의 등록 시점 | 쓸 때 (열어서 고치거나, 문서에 넣거나, 링크를 만들 때) | 큰 버킷에서도 표가 작게 유지된다 |
| 화면에서 한 번에 옮기는 파일 수 | 1,000개 | 요청 하나의 시간 안에 끝나는 양. 더 많으면 CLI |
| 공유 링크 기한 | 1시간, 24시간, 7일 | 미리보기 링크와 같은 선택지. S3 한도가 7일 |
| 공유 링크에 필요한 권한 | 삭제와 같음 (publish) | 비공개 파일을 밖으로 내보내는 일이다 |
| 이미지 변환 | 미리 정한 크기만 | 주소로 아무 크기나 만들 수 있으면 남용된다 |
| 변환 결과 형식 | WebP | 지원 범위와 크기의 균형. `formats`로 AVIF 추가 가능 |
| `_cms/` 폴더 | 파일 관리자에서 숨김 | 썸네일과 변환 결과가 들어 있다 |
| 저장소에서 사라진 파일의 행 | 지우지 않고 "없어짐" 표시 | 문서가 가리키고 있으면 진단이 알려 줘야 한다 |

## 시안에 없는 화면

| 화면 | 따르는 것 | 문구 (제안) |
|---|---|---|
| 공유 링크 만들기 창 | 지금 있는 미리보기 링크 창 (만료 선택, 링크, 복사) | 제목 "링크 만들기", 나머지는 미리보기 링크 창의 문구 그대로 |
| 이미지 초점 지정 | 시안 2번 파일 정보 패널의 미리보기 위에 점 하나 | 새 문구 없음. 점을 끌어 옮긴다. 접근성 이름 "초점" |
| 폴더 이동 진행 | 시안 3번 올리기 진행 패널 | "파일 {n}개 옮기는 중" |
| URL에서 가져오기 창 | 새 폴더 창 (입력 하나와 버튼 둘) | 제목 "URL에서 가져오기", 입력 "주소", 버튼 "취소", "가져오기" |

새 문구가 생기는 곳은 위 표가 전부다. 구현할 때 이 문구로 넣고, PR 본문에 새 문구 목록을 따로 적는다.

## 끝났다고 보는 기준

- CMS로 올리지 않은 파일이 든 MinIO 버킷을 연결하면 파일 화면에서 폴더로 탐색된다
- 모르는 파일을 문서에 넣으면 등록되고 사용처에 잡힌다
- 파일 여러 개와 폴더를 옮길 수 있고, 옮긴 뒤에도 문서의 이미지가 보인다
- 공유 링크가 기한 안에는 열리고 기한 뒤에는 열리지 않는다 (시계를 돌려 테스트)
- write 키로 `create_share_link`를 부르면 거절된다
- Vercel Blob 저장소로 계약 테스트가 통과한다. 통과하지 못한 항목은 문서에 "지원하지 않음"으로 적혀 있다
- 이미지 모듈을 켠 앱에서 `?size=card`가 정한 크기의 WebP를 주고, 정하지 않은 이름은 404다
- 이미지 모듈을 켜지 않은 앱은 `sharp`를 설치하지 않아도 빌드된다 (패키지 설치 테스트)
- 실제 화면을 시안 8번과 같은 크기로 찍어 비교한다
