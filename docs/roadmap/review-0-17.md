# 0.17.0 리뷰 (2026-11-22)

리뷰 에이전트가 0.17.0 작업(묶음 3 마무리)을 읽고 낸 지적. [완료]는 0.17.0에 들어감, [남음]은 다음 버전 몫.

**0.18.0에서 1, 2, 4, 8, 9, 10, 11의 [남음]을 모두 처리함**(리뷰 3~4차까지 반복). 남은 한계는 `UPGRADE-0.18.md`의 "Known limits"에 적음. 12의 DoH 문서 메모는 `apps/docs/content/*/scaling.md`에 있음.

## 서버

1. [완료] P1 필드 숨김이 다른 사본에 남음: `published`, `autosave` 사본의 필드도 지움. [남음] 충돌 응답·버전 비교의 스냅샷에도 같은 투영 적용, 응답 전체 직렬화로 시험.
2. [완료 일부] P1 문서 단위 읽기 규칙: `list`와 `page`가 문서마다 `access.read`를 봄(규칙이 있으면 SQL 페이지 대신 메모리 경로). [남음] 검색 색인·grep·`changedSince`·내보내기·미리보기 링크가 같은 규칙을 쓰게 하는 공통 정책과 표 테스트.
3. [완료] P1 공유 캐시가 CMS·사이트를 구분하지 않음: 키에 이름공간(테이블 스키마와 접두사, 또는 `cache.namespace`). 이 서버의 무효화는 저장소 응답을 기다리지 않고 바로 반영, `settle()`이 기다림.
4. [완료 일부] P1 변경 로그가 커밋 순서 때문에 이벤트를 건너뛸 수 있음: 번호 사이 빈칸이 5초보다 젊으면 거기서 멈추고 다시 봄(따라가기와 `/_changes`, 스트림 모두). 문서의 "정확히"를 고침. [남음] 내용 쓰기와 같은 트랜잭션에서 로그 쓰기(지금은 쓰기 뒤에 따로 씀: 그 사이 프로세스가 죽으면 그 이벤트는 로그에 없음).
5. [완료] P1 zip 한도가 헤더를 믿음: 실제로 풀리는 바이트를 세다 넘으면 멈춤, 중첩 zip까지 한 예산, 항목 수 제한, 범위 검사.
6. [완료] P1 볼 수 없는 필드를 만들 때 넣을 수 있음: 만들 때는 만들어질 문서로 규칙을 봄.
7. [완료] P2 스트림의 `ready` 번호가 아직 보내지 않은 이벤트를 앞지를 수 있음: 번호를 먼저 읽고 대기열을 보냄. 다시 연결할 때 `Last-Event-ID`가 `?since=`보다 우선.
8. [완료 일부] P2 종료 뒤 따라가기 타이머가 다시 걸림: `settle()`이 닫힘 표시. [남음] `outbox.emit` 추적, 사이트 핸들러를 버릴 때 진행 중인 요청·스트림을 기다리기.
9. [완료 일부] P2 커서 검사: 이상한 id는 거절(빈 페이지). [남음] `afterRead`가 정렬 값을 바꾸는 경우 원래 행으로 커서 만들기, 휴지통·댓글·버전 페이지를 저장소에서 자르기.
10. [남음] P2 트랜잭션 없는 드라이버에서 여러 단계 쓰기(릴리스 게시 등)는 반쯤 남을 수 있음: 원자성이 필요한 동작은 트랜잭션 요구. 플러그인 SQL은 `CREATE TABLE`만 보고 판단: 마이그레이션 id·체크섬 기록.
11. [남음] P2 가져오기가 저장은 됐는데 게시가 실패하면 오류로만 보임: 저장·게시 결과를 나눠 보여 주고 실패한 것만 다시. 어드민 zip의 Notion 그림 누락을 목록으로 알림.
12. [완료] P2 지표 경로 이름표가 끝없이 늘 수 있음: 아는 경로만 이름, 나머지는 `/other`. `/metrics`는 `Bearer` 머리만 받음. [남음] DoH 검사는 연결 단계 보장이 아님을 문서에.
